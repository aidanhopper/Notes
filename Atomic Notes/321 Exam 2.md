## GRASP
- General Responsibility Assignment Software Patterns/Principles
- Guided by one main question *"Whose responsibility is it?"*
- Nine principles
	1. **Information expert**: Assign the right responsibilities to the entities with the information needed to fulfill that responsibility.
	2. **Low coupling**: Assign responsibilities so that coupling is low.
	3. **High cohesion**: Assign responsibilities so that cohesion remains high.
	4. **Polymorphism**: When related alternatives or behaviors vary by type, assign responsibility for the behavior using polymorphic operations to the types for which the behavior varies.
	5. **Creator**: Assign class B the responsibility to create an instance of class A if one these is true:
		1. B contains A
		2. B records A
		3. B closely uses A
		4. B has the initializing data for A that will be passed to A when it is created. Thus B is the information expert.
		5. B is a creator of A objects in the domain space.
	6. **Controller**: What first object beyond UI layer receives and coordinates a system operation? The object should represent the overall system.
	7. **Pure Fabrication**: What object should have responsibility when you do not what to violate High Cohesion and Low Coupling? Assign a highly cohesive set of responsibilities to an artificial or convenience class that does not represent a problem domain concept something made up.
	8. **Indirection**: Where to assign responsibility to avoid direct coupling between two or more things? Assign the responsibility to an intermediate object to mediate between other components or services so that they are not directly coupled. The intermediary creates an indirection between other components.
	9. **Protected Variations**: Create interfaces to account for small variations in systems.
